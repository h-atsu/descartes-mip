# PuLPベース自動ラグランジュ分解ライブラリ

この文書は `descartes-mip` の設計上の基準です。実装中に仕様を変更した場合は、
コードと同時にこの文書を更新します。

## 進め方

- 以下のマイルストーンを一つずつ実装する。
- 各マイルストーンでテスト結果と設計上の発見を共有し、確認後に次へ進む。

## Milestone 1: プロジェクト基盤と設計文書

- PuLPとHiGHS、pytestを依存関係へ追加する。
- 公開パッケージ構造、例外、型、テスト構成を用意する。
- 本計画をこの文書に保存し、READMEへ概要とリンクを追加する。
- 最小のPuLPモデルをHiGHSで求解するスモークテストを作る。

## Milestone 2: PuLPモデルの解析と自動分解

- PuLPモデルを変更せず、変数・目的関数・線形制約を内部表現へ変換する。
- 利用者が制約ごとのL1ペナルティを指定できる `SoftConstraint` を実装する。
- 指定された制約を除外した変数–制約グラフから連結成分を求める。
- 孤立変数、目的定数、緩和制約の係数を適切な部分問題へ分配する。
- 抽出した部分問題構造を確認できる診断APIを用意する。

```python
relax = [
    SoftConstraint(capacity_constraint, penalty=100.0),
    SoftConstraint(balance_constraint, penalty=50.0),
]

decomposition = descartes_mip.decompose(problem, relax=relax)
```

実装済みの契約:

- `SoftConstraint` はモデルへ登録済みの `LpConstraint` オブジェクトと、正の有限な
  ペナルティを受け取る。同一制約の重複指定と他モデルの制約は拒否する。
- `Decomposition` は診断用の不変データとして、問題の向き、目的定数、部分問題、
  緩和制約、成立する定数ハード制約を保持する。
- 部分問題の順番は、各成分に属する変数名の辞書順で決定する。変数と制約の表示順も
  元モデルから得た安定順を維持する。
- 変数を持たないハード制約は、成立する場合はコーディネーター側の診断情報へ保持し、
  不成立の場合は分解時に `ModelValidationError` とする。
- 元モデルの目的、制約、変数属性、求解状態、解値は変更しない。ただしPuLPの公開
  `variables()` 読み取りAPIが、内部の変数登録キャッシュと順番を正規化する場合がある。

## Milestone 3: ラグランジュ反復求解

- MILPを内部で最小化形式へ正規化する。
- 不等式 \(g(x)\le0\) には超過ペナルティ \(\rho\max(0,g(x))\) を適用し、乗数を
  \(0\le\lambda\le\rho\) に射影する。
- 等式 \(h(x)=0\) には過不足ペナルティ \(\rho|h(x)|\) を適用し、乗数を
  \(-\rho\le\lambda\le\rho\) に射影する。
- 各部分問題を最適性証明まで求解し、certified双対境界を計算する。
- 部分問題解にスラックを補い、ソフト化後の問題に対する実行可能解と主問題境界を生成する。
- certified双対値と最良主問題境界を使い、投影付きPolyak劣勾配法で乗数を更新する。
- 初期乗数はゼロ、停止条件は最大反復数・全体時間・コールバックとする。

```python
result = descartes_mip.solve(
    problem,
    relax=relax,
    solver=pulp.HiGHS,
    solver_options={"msg": False},
    max_iterations=1_000,
    time_limit=300.0,
    polyak_factor=1.0,
    callback=None,
)
```

実装済みの契約:

- 内部では元の最大化問題も最小化へ符号反転し、不等式は常に `g(x) <= 0` へ
  正規化する。`>=` 制約は式全体の符号を反転する。
- 不等式の乗数区間は `[0, penalty]`、等式は `[-penalty, penalty]` とする。
  初期値は0で、制約名による `initial_multipliers` で上書きできる。
- 各反復で全ての部分問題を最適性証明まで解き、部分問題目的値と定数項から
  certified双対境界を構成する。`Optimal` 以外は `SubproblemSolveError` とする。
- 部分問題解の結合にL1スラックを暗黙に補い、ソフト問題の実行可能な主問題境界を
  毎反復計算する。元の緩和対象制約も満たすかは `hard_feasible` とスラックで示す。
- Polyakステップは、反復中の最良主問題境界と最良certified双対境界の差を、
  正規化制約残差の二乗ノルムで割って計算する。残差が0ならステップも0とする。
- `max_iterations` は正の整数、`polyak_factor` は `(0, 2]` とする。完了反復を受け取る
  callbackがtrueを返した場合にも停止できる。
- 主・双対境界は利用者の元の目的方向で返す。最小化では主上界・双対下界、最大化では
  主下界・双対上界となる。絶対・相対ギャップは内部最小化形式で非負に計算する。
- 部分問題の変数は複製し、元PuLPモデルの求解状態と変数値を変更しない。係数0かつ
  ハード制約に現れない自由変数は、境界内で0に最も近い決定論的な代表値を選ぶ。
- `solve()` は反復前に、すべての決定変数へ有限な下限と上限が明示されていることを
  検証する。いずれかが欠ける場合は、不足する境界を変数ごとに列挙して
  `ModelValidationError` とする。
- この明示的境界要件によって各部分問題の実行可能領域を有界にし、ペナルティ由来の
  乗数box全体で部分問題目的が有限になることを保証する。ハード制約による暗黙の境界は
  推論しないため、安全だが明示的境界のないモデルもv1では保守的に拒否する。
- `decompose()` は構造診断APIとして境界要件を課さず、`solve()` のみが検証する。
- 逐次求解を既定とする。部分問題ごとに指定されたソルバークラスを生成し、時間制限ありでは
  全体期限までの残り秒数を `timeLimit` に設定する。独立な部分問題はMilestone 5の並列モードでも求解できる。

## Milestone 4: 時間制御・結果・障害処理

- 各部分問題の求解時に、全体期限までの残り時間をソルバーへ渡す。
- 時間内に最適性を証明できなかった反復は、境界や乗数更新に使用しない。
- 直前までのcertified結果を保持して `time_limit` 終了として返す。
- ソルバー側の停止精度に伴う小さな時間超過を許容し、実測時間を記録する。
- ハード部分問題の infeasible、unbounded、solver error を部分問題ID付きで報告する。
- 終了理由、最良ソフト実行可能解、スラック、元制約違反量、主・双対境界、ギャップ、
  乗数、分解構造、反復履歴を結果に含める。
- ソフト化後の実行可能性と、元のハード制約に対する実行可能性を明確に区別する。

実装済みの契約:

- `time_limit` は正の有限秒数または `None` とし、モデル解析を含む `solve()` 全体の
  monotonic wall-clock予算として扱う。
- 各部分問題の直前に残り時間を再計算し、新しいソルバーの `timeLimit` へ渡す。
  時間制限なしの場合だけ `None` を渡す。
- `Not Solved` または期限到達によって最適性未証明となった反復は、途中まで得た部分問題
  解をすべて破棄し、境界・履歴・乗数を更新しない。`Infeasible` と `Unbounded` は時間切れと
  混同せず `SubproblemSolveError` とする。
- 期限をわずかに超えても全部分問題が `Optimal` なら、その反復はcertifiedとして採用して
  から `time_limit` 終了とする。
- 結果には `elapsed_time`、`timed_out_subproblem`、`has_certified_bounds` を含める。
  各完了反復と部分問題にも累積・個別の実測時間を保存する。
- 完了反復がない場合、主・双対境界とギャップは目的方向に応じた無限値、解とスラックは
  空、`soft_feasible` と `hard_feasible` と `has_certified_bounds` はfalseとする。
- ソルバー生成や求解時の例外、時間切れ以外の未定義状態は、部分問題IDを含む
  `SubproblemSolveError` とする。

## Milestone 5: 並列求解と公開品質

- 逐次求解を既定とし、`parallel=True` と `workers` を追加する。
- 部分問題ごとに独立したソルバーインスタンスを生成する。
- 並列実行後は部分問題ID順に決定論的に集約する。
- チュートリアル、完全なサンプル、APIドキュメントを追加する。
- HiGHSとCBCの明示したPuLPソルバークラスを受け付け、それ以外は検証エラーとする。
- CBCについて基本的な互換テストを行う。

実装済みの契約:

- `parallel=False` を既定とし、`parallel=True` で複数の部分問題をスレッドプールへ
  投入する。`workers` は正の整数または `None` で、並列モードでのみ指定できる。
- 指定されたソルバークラスを各部分問題・各反復で一度ずつ呼び、必ず独立したインスタンスを
  得る。インスタンス生成はロックで直列化し、生成後の求解だけを並列実行する。
- 並列タスクの完了順には依存せず、結果、目的値、履歴を部分問題ID順に集約する。これにより
  同じ決定論的ソルバーを使う限り、逐次・並列で同じ数値結果と履歴順を得る。
- 一つでも部分問題が時間内に最適性を証明できなければ、逐次モードと同様に反復全体を破棄する。
  各インスタンスには生成時点の全体残り時間を渡すため、ソルバー停止精度やスレッド終了待ちに
  よる小さなwall-clock超過は許容する。
- 部分問題が一つだけの場合は、`parallel=True` でもスレッド生成を省略して逐次経路を使う。
- HiGHSを既定かつ公式検証対象とし、同梱CBCによる基本的な逐次・並列互換性もテストする。
  サポートするクラスは `pulp.HiGHS` と `pulp.COIN_CMD` に限定し、それ以外のクラスや
  インスタンスは求解前に `ModelValidationError` とする。
- ソルバー固有のキーワードは `solver_options` で受け取る。`msg=False` を既定とし、全体時間
  予算から設定する `timeLimit` は予約済みとして利用者による上書きを拒否する。
- 公開APIの契約を `docs/api.md`、モデル構築から結果確認までの完全な例を
  `examples/tutorial.py` に置く。パッケージは `py.typed` を含み型情報を公開する。

## Public Interfaces

- `SoftConstraint`: PuLP制約と正の有限なL1ペナルティを保持する。
- `decompose()`: 求解せずに自動分解結果を検査する。
- `solve()`: 分解、部分問題求解、乗数更新を実行する。
- `Decomposition`: 成分、変数、ハード制約、緩和制約の対応を保持する。
- `LagrangianResult`: 最良解、境界、乗数、履歴、終了理由、保証状態を保持する。
- `IterationRecord`: 各反復の残差、ステップ幅、主・双対値、経過時間、部分問題状態を保持する。
- `SolverClass`: サポート対象のPuLPソルバークラスを表す。
- `SUPPORTED_SOLVERS`: `solve()` が受け付けるソルバークラスのタプル。

## Test Plan

- 手計算可能な2成分MILPで、自動分解・ラグランジュ関数・乗数更新を検証する。
- `<=`、`>=`、`==` の残差、乗数区間、L1スラックを検証する。
- 最小化・最大化、連続・整数・二値変数、孤立変数、目的定数を検証する。
- 直接構築したソフト制約付きMILPと、分解求解の主・双対境界を比較する。
- 時間切れの未完了反復がcertified結果を変更しないことを確認する。
- 逐次・並列で同一結果と決定論的な履歴を確認する。
- 無効な重み、別モデルの制約、重複指定、非線形式、infeasible、unboundedを検証する。

## Assumptions

- Python 3.12、PuLP、HiGHSをv1の基準環境とする。
- 対象は線形目的・線形制約を持つMILPとする。
- L1型ソフト制約だけを扱い、二乗・一般凸ペナルティは対象外とする。
- 利用者が緩和制約と重みを明示し、変数グループは指定しない。
- 実行可能解とはソフト化後の問題に対するものであり、元制約を満たす修復処理は提供しない。
- Bundle法、手動分割、分枝限定との統合、厳密なハード時間制限は将来拡張とする。
